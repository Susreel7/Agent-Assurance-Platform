# Console build spec

Binding contract for `services/web`. Read `../../NAMING.md` section 5 and 6 first — the
vocabulary table is not advisory, it is what every label in the UI must say.

## What this is

One React bundle serving two audiences, gated by scope:

- **Assurance console** — our tenant's own staff. Full fleet view.
- **Trust portal** — a named customer's security team and their external auditors.
  Read-only, scoped to one engagement, must never leak another customer's existence.

## Hard constraint: it must run with no backend

There is no Docker and no Postgres on the build machine. `npm run dev` has to render every
screen with realistic data. So:

- `src/mocks/fixtures.ts` holds a synthetic estate: **40 agents**, 8 customers, 12 engagements,
  ~90 releases, ~400 evidence events, ~60 findings, a graph of ~200 nodes.
- `src/api/client.ts` reads `import.meta.env.VITE_API_MODE`. When it is `mock` (the default in
  dev), every call resolves from fixtures after a 120–400 ms delay so loading states are real.
  When it is `live`, it fetches `/v1/...`.
- Fixtures are generated by a seeded PRNG (`src/mocks/rng.ts`, mulberry32, seed `0xA4P`) so the
  numbers are identical on every reload. A demo that reshuffles itself is not a demo.

The fixture data is also the investor demo. Make it plausible: an insurance claims agent, a
KYC agent, a payments reconciliation agent. Real-sounding team names. One agent must be
**suspended because its model provider changed** — that is the 90-second demo on HLD page 5.

## Design language

Dense, quiet, information-first. This is a tool an auditor reads, not a marketing page. No
gradients, no shadows beyond a hairline, no rounded-2xl cards, no emoji, no icon fonts —
inline SVG only.

`src/styles/tokens.css` defines everything as CSS custom properties; Tailwind extends from
them so a token change propagates.

```
--ink-900 #0f1115   text primary        --bg-base  #fbfbfc
--ink-600 #4a5160   text secondary      --bg-panel #ffffff
--ink-400 #8a90a0   text muted          --bg-sunk  #f4f5f7
--line-200 #e4e6eb  hairline            --line-300 #d0d3da

state colours — used for state, never for decoration
--ok-fg #1c6b3f    --ok-bg #e8f5ed
--warn-fg #8a5a00  --warn-bg #fdf3e0
--risk-fg #a32c22  --risk-bg #fdeceb
--info-fg #1f4e9c  --info-bg #e9f0fb
--mute-fg #4a5160  --mute-bg #f0f1f4
```

Type: system UI stack for prose, `ui-monospace, SFMono-Regular, Menlo, monospace` for every
URN, digest, semver and identifier. 13px base in tables, 14px in body, `font-variant-numeric:
tabular-nums` on all numeric columns.

Layout: fixed 240px left rail, content max-width 1440px, 24px gutters. Tables are full-bleed
within the panel with sticky headers.

## Screen requirements

### Dashboard
Six metric tiles across the top: agents in production, accredited, suspended, material changes
this week, open critical findings, SLO attainment. Each tile shows a 30-day sparkline and is a
link, never a dead number.

Then: an "attention required" list (suspended accreditations, drifted engagements, overdue
attestations, critical findings) ordered by consequence, not by time. A stacked bar of agents by
lifecycle state. A donut of accreditation states. A 14-day column chart of releases split
material / needs-review / immaterial. A recent-releases strip.

The point of this screen: someone who opens it cold should know within five seconds whether
anything is wrong and what to click.

### Releases — `/releases/:releaseId`
This is the screen the product is sold on. It must make a source-control diff look useless.

Header: agent URN, `from_semver -> to_semver`, release state, proposed by, impact badges,
accreditation consequence banner (green "approval stands" / amber "revalidation required" /
red "approval suspended", with the rule that fired named explicitly).

Body: changes grouped by the 16 `ChangeCategory` values in enum order. Each change row shows
category label, a one-line `summary` (this is the sentence that makes it legible), before → after
rendered by type (scalars inline, objects as a compact key diff), impact badges, severity, the
materiality verdict, and `rules_fired` as monospace chips.

A right-hand rail holds: "what this means for approvals" — which accreditations and which
customers are affected by name. Then the adjudication control for `needs_review` changes.

Also add a "raw descriptor diff" tab that shows the two JSON documents side by side, collapsed
by default — its purpose is to demonstrate how much worse the raw view is.

### Agents
Table: URN (mono), display name, owning team, lifecycle state, framework, environment,
posture score, accreditation state, drift indicator, last release. Filter by state, team,
framework, accreditation state, customer. The drift column is the money column: deployed
version differs from accredited version.

Detail page tabs: Overview (posture with contributing factors always expanded — never an
unexplained number), Bill of materials (grouped by `component_kind`), Versions (timeline,
baseline marked), Releases, Evidence, Graph neighbourhood, Ownership, Accreditations, Findings.

### Evidence
Explorer with kind / agent / engagement / time filters. Table of events showing occurred_at,
recorded_at, kind, agent, actor, action, outcome, region, data classes, and a truncated digest.
Above it, a **chain verification panel**: batch sequence, Merkle root, previous batch digest,
verified / broken, and a "verify inclusion proof" control for a selected event that shows the
audit path. No event row ever shows content — that is the product's central promise.

### Graph
Cytoscape, `cose-bilkent`-less (use the built-in `cose` layout, no extra package). Node shapes
by kind, edge style solid for `declared` and dashed for `observed`. The **declared-versus-observed
gap must be visually obvious** — that gap is the most valuable data in the product.
Controls: focus node, depth 1–4, filter by edge type, and a blast-radius mode that selects a
node and highlights everything transitively reachable with a count.

### Customers
List with sector, jurisdiction, criticality, engagement count, required frameworks, readiness
percentage. Detail shows the **readiness view**: per framework, a bar of controls we can
evidence versus controls we cannot, with the gap list naming each unanswerable control and why.

### Engagements
List showing customer, state, agents in scope, permitted regions, SLO attainment, and drift
count. Detail: the agent scope table with `accredited_version` beside `deployed_version` and a
loud marker when they differ.

### Accreditations
Queue grouped by state (the HLD page 5 state machine: draft, submitted, approved, suspended,
expired, withdrawn). Detail shows control-by-control answers with the evidence that satisfies
each, the pack download, the signature and its verification status, and the state-transition
history with actor and timestamp.

### Findings
Triage table: severity, source (probe / cve / drift), category, agent, state, first seen,
remediation due, with overdue rows marked. Grouped severity counts at the top.

### Policy
Policy versions with effective dates and signatures; a decisions table showing outcome
(allow / deny / redact / reroute / require_approval) with reason codes and a link to the
evidence event.

### SLA
Per-engagement SLO table: kind, target, current attainment, window, breach count, computed
service credit. An attainment chart per SLO.

### Trust portal
Separate shell — no left rail, a customer-branded header, and a visible "scoped to
<engagement>" statement. Shows only: accredited agents in that engagement, their accreditation
state and pack downloads, SLO attainment, open findings by severity without internal detail,
residency proof summary, and the evidence chain verification result. It must be obvious that
nothing here reveals another customer.

## Rules

1. Every table has real loading skeletons, a real empty state and a real error state.
2. No `any`. `noUncheckedIndexedAccess` is on — index access needs a guard.
3. No chart library. Inline SVG only.
4. No new dependency beyond what `package.json` already lists, except `@tanstack/react-table`
   is **not** permitted either — `DataTable.tsx` is hand-written.
5. Accessible: every interactive element reachable by keyboard, `aria-label` on icon-only
   buttons, focus rings visible, `<th scope="col">` on table headers.
6. `npm run build` must pass with zero TypeScript errors.
7. Currency is GBP where a service credit is shown. Dates render as `2026-09-13 14:22 UTC`
   in tables and relative ("3 days ago") in prose, never the reverse.
